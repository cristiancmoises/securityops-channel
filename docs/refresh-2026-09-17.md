# Package refresh — 17 September 2026

[Português (Brasil)](refresh-2026-09-17.pt-BR.md)

This refresh checks the channel's exported packages against their upstream
stable releases and adds the River 0.4 runtime used by the local Wayland
window-manager project. It targets GNU Guix on x86_64 Linux.

The review is still in progress. The table separates successful builds from
work that has not finished. Nothing here certifies a complete desktop for
physical GPU, input-device, suspend or session-lock use.

Chrome's downloaded hash was checked against Google's APT metadata; the
portable Chromium archive matched its upstream release digest. Both browser
smokes, initially with portable Chromium 153.0.8010.36-1, used temporary profiles
without `--no-sandbox`. A separate windowed
test in River inside Sway ran without `--disable-gpu`: both browsers rendered
WebGL through NVIDIA/ANGLE, returned the expected canvas pixel and accepted
Unicode text through the DevTools protocol. Their sandbox status pages reported
PID/network namespaces and Seccomp-BPF enabled. Temporary profiles and the
nested session were removed, and Sway returned to its original mode. This
does not exercise physical typing, video codecs or every sandbox boundary.
These are binary packages, so the checks do not replace upstream source suites.

The final release check found portable Chromium 153.0.8010.47-1. Its archive
hash and normal Guix build passed. The bundled ChromeDriver previously lacked
the wrapper's library environment and failed to load NSS. It now uses the same
wrapper phase as the browser; both installed version checks pass. A private
loopback check also verified the driver's HTTP status without starting a browser
session. The NVIDIA variant and installed-profile rendering retest are pending.

Chrome's desktop integration now points both desktop IDs to the Guix wrapper
without discarding URL arguments or the incognito action. The portal entry keeps
its original `NoDisplay=true` setting. A regression check reproduced the invalid
`/usr/bin` commands and lost arguments, then passed against the rebuilt package;
both desktop files also passed `desktop-file-validate`.
The rebuilt package then passed the same nested NVIDIA rendering, Unicode and
sandbox-status checks through the installed application and River profiles.

The latest Ungoogled Chromium source release is 153.0.8010.47-1. Its portable
binary release has a separate schedule. Updating the source-built definition
is still in progress; the older Guix source alias must not be confused with
the newer portable package.

LibreWolf 156 combines the pinned Firefox release, LibreWolf overlay and the
locale revision from Firefox's release metadata. Assembly uses local inputs,
preserves the Firefox locale license and applies LibreWolf's own translations
as a separate overlay. It needs NSS 3.129 and NSPR 4.40; neither dependency is
silently replaced by a lower version to pass configure.

The first build compiled and installed the browser, then failed in Guix's
inherited `glxtest` wrapper. Firefox 156 replaces that executable with `gfxtest`,
which also probes VA-API and Vulkan. The recipe now wraps the new executable
and supplies all five library directories used by its dynamic loaders. A
focused test reproduced the old failure and passed with the updated phase.
The complete rebuild and NVIDIA library substitution passed. Guix's inherited
RUNPATH validation remains disabled for this package's runtime library loading;
the phase's successful exit does not represent an ELF dependency audit.
In a fresh profile inside River, the packaged `gfxtest` reported NVIDIA EGL,
and the browser's own WebRender log independently identified the NVIDIA renderer.
Unicode input and the canvas pixel in a WebDriver screenshot passed. All four observed content
processes had Seccomp filtering and `NoNewPrivs` enabled, with no effective
capabilities. No sandbox-disabling options or privileged WebDriver diagnostics
were used. Canvas readback differed from the rendered pixel, consistent with
LibreWolf's privacy behavior; the test does not audit that protection. WebGL2 was
unavailable in the test profile, without a graphics-preference override.
Geckodriver applies its documented
[automation preferences](https://firefox-source-docs.mozilla.org/testing/geckodriver/Profiles.html#automation-preferences)
to temporary profiles, so this is not a check of untouched browser defaults.
These checks do not validate video
decoding, every sandbox boundary or the physical desktop session.

Tor Browser's recipe now binds the updated inputs before evaluating inherited
Guix phases. A lowered-builder regression check caught and corrected an older
Tor geoip dependency that survived the declared input replacement. The full
browser build and NVIDIA library substitution passed; the installed configuration
selects Tor 0.4.9.12. Its inherited upstream
browser suite and RUNPATH validation remain disabled and are not counted as
passing tests.

An offline test in a fresh profile passed Unicode input, a rendered canvas pixel
and active packaged NoScript 13.6.33.1984. WebRender identified the NVIDIA GPU;
all six observed content processes had Seccomp filtering, `NoNewPrivs` and no
effective capabilities. The matching geckodriver attached to the already running
browser, avoiding its usual profile preference overrides. Only the two automation
preferences were supplied; browser privacy, proxy and extension preferences were
left in place. WebGL2 was unavailable, and canvas readback differed from the visible
pixel; neither result is a privacy audit. The fixture used private network and
mount namespaces, loopback only, and `TOR_PROVIDER=none`. Cleanup passed and Sway
returned to its original mode. This checks offline browser operation, not Tor
bootstrap, circuits, anonymity or connections to remote sites.

NSS built successfully with all 21 STANDARD test groups passing: 33,591
assertions passed and none failed. One summary entry is classified “Unknown”;
matching the test driver and build manifest identifies it as the unbuilt
`mozpkix_gtest` skip in the Make build. The detailed HTML was not retained,
so this attribution is reconstructed from the source and build log.
Guix's inherited certificate-fixture date remains 2025-02-05; it applies to
tests, not the installed library. The inherited patch that excludes network
PKIX/OCSP tests also remains. Other cycle/dependency skips and NSPR's absent
check target are not counted as passed tests. LibreWolf itself retains Guix's
disabled upstream browser suite; the runtime checks above are separate smoke tests.

MoneyPrinterTurbo now uses a public Git commit and a source snippet instead
of a locally edited tarball. Bundled sample music and fonts without included
redistribution terms are removed; the installed WenQuanYi font supplies the
default. The 38 tests cover offline helpers. The existing first-run pip venv
is still outside a complete Guix dependency closure, and external media/AI
providers were not exercised.

## River runtime

The new `(securityops packages river)` module exports River 0.4.8, Foot
1.28.0, Fuzzel 1.15.0, wlr-randr 0.5.0, swaybg 1.2.2, mako 1.11.0 and
swaylock 1.8.6, with Wayland 1.26.0,
wayland-protocols 1.49, libinput 1.31.3, libevdev 1.13.7 and libxkbcommon
1.13.2. The existing stable wlroots 0.20.2, Xwayland 24.1.13, Pixman 0.46.4,
fcft 3.3.3 and Zig 0.16.0 remain in use. Prereleases were excluded.

Channel is explicitly versioned `0.4.1-1.94a3d6c`: a pinned snapshot after
its latest 0.4.1 tag. Its source manifest says 0.4.2, but there is no matching
stable 0.4.2 release. This distinction matters when comparing versions.

The dependency builds passed 26 Wayland tests, 191 protocol tests, 28
libxkbcommon tests and six Channel/libtributary tests. River's Zig checks and
Foot's unit test passed. libevdev, libinput and Xwayland retain their upstream
hardware or environment skips. No newly failing test was disabled.

Wayland's generated API documentation is installed. Its new mdbook manual is
shipped as Markdown source because the pinned Guix does not provide mdbook.
The recipe's BSD-3-Clause notice is retained separately from the channel's
GPL license; packaged components keep their upstream licenses.

A private headless integration check exercised two outputs, five windows,
Foot and Fuzzel. Local nested NVIDIA testing found a keyboard-repeat startup
issue: River kept stale seat metadata when reconfiguration replaced its active
keyboard group. A focused patch passed 11 private integration scenarios with
two keyboards, including shared groups, keymap changes and device removal.
A separate patch removes an incorrect missing-seat log after successful
assignment. A third patch fixes a layer-shell negotiation deadlock: Mako can
change its requested size after the first configure but before attaching its
first buffer. River now sends the next configure while preserving the protocol
rules for unmapped surfaces. The regression fails on unmodified River and passes
all six scenarios with the patch, including remapping and exclusive-area cleanup.
All 11 keyboard scenarios were rerun successfully with this change.

Private headless checks also confirmed swaybg's rendered color, Mako's Unicode
notification rendering, dismissal and history, and swaylock's lock/unlock protocol
sequence. Unlocking used a signal inside that private compositor; it does not
validate PAM authentication or a physical session lock. These three helper
projects define no upstream unit tests; their Meson check phases ran as supplied.

Launcher cleanup fixes passed 22 tests. The applied machine launchers then
passed 23 fixtures covering cleanup, application selection and the pinned locker.
The compiled manager reproduced all 74 configured bindings without changing
their key combinations.

A separate profile containing nine applications was installed, and the dedicated
local runtime reached generation 7 while preserving its earlier generations.
This did not activate Guix Home, the system candidate or audio services. The
complete system candidate also built successfully; its physical session has not
been activated or tested.

Testing found that the existing Fish configuration prepended an older profile
to PATH. A Fish wrapper used only by River now restores the selected application
prefixes, SHELL, ICECAT_SYSTEM_DIR and desktop search path after reading the user's
normal configuration. Other paths, functions and arguments remain available;
HOME and the user's Fish/Kitty configuration are unchanged. Five checks with
real Fish passed, including the current configuration, deliberate environment
overrides, Unicode arguments and Kitty shell integration.

The final private test inside Sway passed NVIDIA/GLES2 rendering, automatic
Kitty with Fish 4.9.3, ABNT2 repeat 25/600 before input, window transitions and
private diagnostics. Commands run after Fish's configuration selected the new
applications; all 14 commands across five browser desktop files and their actions
resolved to the intended packages. The packaged NoScript path and swaylock 1.8.6
selection were checked without opening a browser or locking the host session.
Cleanup removed the private runtime and its processes and restored Sway's default
mode. Existing Sway and audio processes were preserved. Physical-session acceptance
remains outstanding. The window manager is still experimental and is not exported
as a production package by this refresh.

A separate private Xwayland check mapped an xterm and preserved its Unicode
title, including a valid COMPOUND_TEXT encoding. The fixture verified that both
Xwayland's Wayland and XWM sockets belonged to the test River instance before
starting the client. A real screenshot confirmed the terminal, and cleanup
removed the private runtime and tracked processes and restored Sway's mode.
This covers one X11 client, not compatibility with every X11 application.

## Audio packages

The new `(securityops packages audio)` module exports explicit bindings
`pipewire-latest` (1.6.8) and `wireplumber-latest` (0.5.17), with public Git
commits and recursive source hashes. WirePlumber uses the updated PipeWire input.
The builds passed all 51 PipeWire and 56 WirePlumber tests. PipeWire's license
metadata now reflects its upstream MIT, LGPL-2.1-or-later and GPL-2.0-only scopes
and exceptions.

A separate private PipeWire server accepted WirePlumber's policy metadata and
answered `wpctl status`. Hardware and bus monitors were disabled for this test;
there were no device/node objects or sound/video device descriptors. Both
processes exited cleanly. This checks the new client/server pair without changing
the running audio service. Hardware audio, Bluetooth, portals and existing user
policy fragments still need their own validation before service activation.

All 49 XLibre source pins were checked. Only the three drivers above changed;
server 25.2.2 remains current. An older GitHub release marked “latest” was not
used to downgrade the server. No GPU driver was activated during this review.

See [the package index](../PACKAGES.md) for all exported recipe versions.
The 23 current security, utility, monitoring and container definitions were
realized successfully. Nmap ran 57 Python tests plus its NSE unit tests without
scanning any hosts; Radare2 reported 72 passed, six skipped and no failures.

packaged runtimes remain limitations, not passing results.

Both Emacs 31.1 variants finished their builds. Each reported 8,278 expected
test results, no unexpected results and 469 upstream skips out of 8,747 tests.

## Channel validation

An immutable snapshot of the uncommitted tree passed Guix's standard channel
module compilation and package-cache build: 22 modules compiled, including the
audio module, and all three River patches resolved from the compiled channel.
Guix and Nonguix inputs were authenticated at their pinned revisions. The
Chromium source update was still outside that snapshot. The local snapshot has
no signed commit, so this check does not authenticate the new channel changes.
The final signed revision still needs an authenticated pull before publication.
No user profile was activated by this compilation check.
